# Техническое задание: RoomFlow AI

## 1. Назначение

Real-time система детекции, трекинга и AI-идентификации людей через потолочную камеру, направленную на дверной проём. Подсчёт входящих/выходящих, формирование карточек персон с AI-описанием внешности, веб-интерфейс для просмотра статистики и управления.

---

## 2. Архитектура (Event Bus / Pub-Sub)

```
IP Camera (MJPEG/RTSP)
  │
  ├── OpenCV → захват кадра
  ├── YOLOv8n + ByteTrack → детекция + трекинг
  ├── PeopleCounter → логика зоны двери, публикует события
  │     │
  │     ▼
  ├── EventBus (Pub/Sub)
  │     │
  │     ├──► LoggerSubscriber — пишет в SQLite, обновляет счётчики IN/OUT
  │     │     │
  │     │     └──► публикует entered_ai / exited_ai
  │     │
  │     └──► AISubscriber — читает crop с диска → moondream → обновляет карточку
  │
  ├── FastAPI + Jinja2 → веб-интерфейс (читает только из БД)
  └── run_server.sh → watchdog (авторестарт при падении)
```

### Принцип

**Publisher (издатель):** `PeopleCounter` — только детектирует пересечение зоны двери и публикует стандартизированные события в шину. Не имеет доступа к БД или AI.

**Event Bus:** Асинхронная шина сообщений. При публикации события каждый подписчик вызывается в отдельном daemon-потоке.

**Subscribers (подписчики):**
- **LoggerSubscriber** — получает событие → инкрементирует счётчик → пишет запись в `events` таблицу → публикует `entered_ai`/`exited_ai` для AI-подписчика
- **AISubscriber** — получает событие с `event_id` → читает crop-файл с диска → отправляет в moondream → создаёт/обновляет карточку персоны

Благодаря этой архитектуре PeopleCounter не блокируется на запись в БД или ожидание AI — он просто детектирует и публикует.

## 3. Компоненты системы

### 3.1. Шина событий (backend/event_bus.py)
- Класс `EventBus`
- Методы: `subscribe(event_type, callback)`, `publish(event_type, data)`
- Каждый callback выполняется в отдельном daemon-потоке
- Ошибки подписчиков логируются в `logs/pipeline_error.log`

### 3.2. Сервер (backend/main.py)
- **FastAPI** приложение
- Роуты: API, страницы, MJPEG-стрим
- При старте: инициализирует `PersonDB`, вычисляет счётчики через `SELECT COUNT(*)` из `events`, запускает `CameraPipeline`

### 3.3. Пайплайн (backend/pipeline.py)

#### SharedState
- Общее состояние: счётчики `entered`/`exited`, FPS, зона двери, текущий кадр
- Счётчики при старте вычисляются из `events` таблицы (не из `settings`)

#### CameraPipeline (threading.Thread)
- Цикл захвата/детекции
- Создаёт `PeopleCounter`, `EventBus`, подписчиков
- На каждом кадре: читает кадр → YOLO + ByteTrack → `counter.update()` → обновляет стрим

#### PeopleCounter
- Логика пересечения зоны двери
- **Вход:** человек был в зоне → вышел из зоны → публикует `entered`
- **Выход:** трекер потерял человека (задержка 0.5 с) → публикует `exited`
- Cooldown 100px/10s против флапа
- Не имеет доступа к БД или AI

#### Subscribers (замыкания)
- `make_logger_subscriber(state, db, event_bus)` — подписчик на `entered`/`exited`
- `make_ai_subscriber(db, llm)` — подписчик на `entered_ai`/`exited_ai`

### 3.4. Детектор (backend/detector.py)
- Обёртка над Ultralytics YOLO + ByteTrack
- `detect(frame, track=True)`, `get_objects(results)`, `get_annotated_frame(results)`

### 3.5. LLM-клиент (backend/llm_client.py)
- HTTP-клиент к Ollama (OpenAI `/v1/chat/completions`)
- Vision-запрос: text + base64-изображение
- Читает URL модели из `settings` таблицы при каждом запросе
- Возвращает `{"person_id": int, "description": str}`
- Пустой ответ модели → `{"person_id": 0, "description": "[empty response from model]"}`

### 3.6. База данных (backend/database.py)
- SQLite (`data.db`)
- **Методы PersonDB:**
  - `count_events(type)` — `SELECT COUNT(*)` для вычисления счётчиков при старте
  - `save_entry_event(track_oid, crop_path, screenshot_path, entered_count, exited_count)` — вставка события входа
  - `save_exit_event(track_oid, person_id, screenshot_path, crop_path, entered_count, exited_count)` — вставка события выхода
  - `get_recent_events(limit)` — выборка для лога
  - `assign_event(event_id, person_id)` — привязать персону к событию
  - `resolve_event(event_id, ai_description)` — создать новую персону и привязать
  - `clear_events()` — очистить таблицу (Reset Counters)
  - `reset_persons()` — удалить персон (события остаются, `person_id → NULL`)

### 3.7. Конфигурация (backend/config.py)
- Camera: IP, URL (MJPEG/RTSP), разрешение
- Models: YOLO, LLM, Vision
- Logs: директория, флаги
- Настройки из БД (`settings` таблица) переопределяют config.py (LLM URL, Vision Model, Door Zone)

### 3.8. Веб-интерфейс (templates/)
- **Dashboard** (`/`) — MJPEG-стрим, счётчики IN/OUT/NOW, Event Log (из БД), Person Crossings (из БД)
- **People** (`/people`) — список персон + галерея скриншотов (с фильтром по дате)
- **Person Detail** (`/people/{id}`) — карточка персоны, AI-описание, таймлайн событий
- **Logs** (`/logs`) — таблица всех событий из БД
- **Settings** (`/settings`) — зона двери, LLM URL, Vision Model, Reset Counters/Persons, Dedup

## 4. Зона двери

Конфигурируется в `/settings` (нормализованные 0.0–1.0):
- **door_left** / **door_right** — границы по ширине кадра
- **door_top** / **door_bottom** — границы по высоте

Условие "человек в зоне":
```
door_left <= cx <= door_right AND door_top <= y2 <= door_bottom
```
где `cx` — центр bbox, `y2` — нижняя граница bbox (ноги).

### Логика входа:
1. Человек был в зоне (`was_in_door = True`)
2. Человек вышел из зоны (`in_door = False`)
3. → публикуется `entered` событие (с сохранённым скриншотом и crop)

### Логика выхода:
1. Трекер потерял человека
2. Человек был в зоне или рядом (`in_door_now OR in_door_prev`)
3. Задержка 0.5 с (ожидание возможного reacquire)
4. → публикуется `exited` событие (с последним сохранённым `exit_frame`)

## 5. AI-идентификация (moondream)

Выполняется в `AISubscriber` (асинхронно, после записи события в БД):

### Запрос:
- Изображение: crop человека (base64, JPEG quality 80)
- Текст: список известных персон с их AI-описаниями
- Промпт: "Analyze the person. If matches known → return ID, else 0. Describe clothing, gender, age."

### Ответ:
```json
{"person_id": 0, "description": "Male, 30-40, blue jacket, jeans, carrying a backpack"}
```

### Матчинг:
- `person_id > 0` → событие привязывается к существующей персоне (`assign_event`)
- `person_id = 0` → создаётся новая персона (`resolve_event`), описание сохраняется

## 7. База данных (SQLite)

### Схема

```sql
CREATE TABLE persons (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    name            TEXT NOT NULL DEFAULT 'Person',
    gender          TEXT DEFAULT '',
    clothing        TEXT DEFAULT '',
    ai_description  TEXT DEFAULT '',
    created_at      TEXT NOT NULL DEFAULT (datetime('now')),
    date            TEXT NOT NULL DEFAULT (date('now'))
);

CREATE TABLE events (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    person_id       INTEGER REFERENCES persons(id),
    type            TEXT NOT NULL CHECK(type IN ('entered','exited')),
    timestamp       TEXT NOT NULL DEFAULT (datetime('now')),
    screenshot      TEXT DEFAULT '',
    crop            TEXT DEFAULT '',
    ai_description  TEXT DEFAULT '',
    track_oid       INTEGER DEFAULT NULL,
    entered_count   INTEGER DEFAULT 0,
    exited_count    INTEGER DEFAULT 0
);

CREATE TABLE face_images (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    person_id       INTEGER NOT NULL REFERENCES persons(id),
    filename        TEXT NOT NULL,
    created_at      TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE settings (
    key   TEXT PRIMARY KEY,
    value TEXT NOT NULL
);
```

### Файловое хранилище

```
logs/
├── YYYY-MM-DD/
│   ├── person_{oid}_entered_{time}.jpg   -- полный скриншот входа
│   ├── person_{lid}_exited_{time}.jpg    -- полный скриншот выхода
│   └── crops/
│       ├── crop_oid{oid}_{time}.jpg      -- crop человека при входе
│       ├── exit_oid{lid}_{time}.jpg      -- crop человека при выходе
│       └── person_{pid}_{time}.jpg       -- face image (для карточки)
├── faces/  (legacy)
└── pipeline_error.log
```

## 10. Текущие ограничения

1. **SIGABRT от OpenCV MJPEG:** Чтение MJPEG через OpenCV периодически (30-60с) вызывает SIGABRT. Решение: watchdog `run_server.sh` перезапускает процесс.
2. **Нет аутентификации:** Любой, у кого есть доступ к порту, может смотреть видео и менять настройки.
3. **Отсутствие синхронизации:** `state.entered += 1` не атомарно (но на практике race condition маловероятен — события не чаще 1/10с).
4. **Аудио отключено:** Whisper ASR реализован, но не подключён к пайплайну.
5. **Нет авто-архивации:** Старые события и скриншоты не удаляются.
6. **Производительность AI:** moondream на CPU ~15 секунд на запрос; очередь растёт при интенсивном трафике.
7. **Нет контейнеризации (Docker).**
